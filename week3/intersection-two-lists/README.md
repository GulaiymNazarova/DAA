# Intersection of Two Linked Lists

## 1. Problem

Даны два связных списка. Надо найти узел, с которого они начинают пересекаться. Пересечение это когда один и тот же узел в памяти, а не просто одинаковые числа. Списки могут быть разной длины.

## 2. Approach

Сначала считаю длину обоих списков. Потом смотрю какой длиннее, и двигаю указатель на этом списке вперёд на разницу длин. Тогда оба указателя оказываются на одинаковом расстоянии от конца, и можно идти синхронно.

Иду одновременно по двум спискам и сравниваю указатели через ==. Как только они совпали — это и есть точка пересечения. Если дошли до null — пересечения нет.

Пример: список A = a1 -> a2 -> c1 -> c2, список B = b1 -> b2 -> b3 -> c1 -> c2.
Длины 4 и 5. Разница 1. Сдвигаю B на один: указатель B теперь на b2.
Дальше идут вместе: a1 и b2, a2 и b3, c1 и c1 — совпало. Возвращаю c1.

Проблема была в том, что я сначала сравнивала значения через .val, а не ссылки. И тогда на тестах где просто одинаковые числа, но разные узлы, ответ был неправильный. Поняла когда прогнала тест где два одинаковых списка без пересечения, а программа говорила что пересечение есть. Заменила на ==.

Ещё сначала делала вложенные циклы: для каждого узла A пробегала весь B. Работало, но медленно. Потом придумала с длинами.

## 3. Time Complexity

Time: O(n + m), где n и m длины списков. Потому что прохожу каждый список дважды — раз для длины, раз для поиска. Это всё равно линейно.
Space: O(1), только указатели и переменные с длинами.

## 4. Reflection

Моё решение уже оптимальное. Есть вариант покрасивее без подсчёта длин: когда один указатель доходит до конца, переставлять его на голову другого списка. Тогда они встретятся сами. Сложность та же, но кода меньше. Я этот способ не сразу поняла, поэтому оставила свой.
